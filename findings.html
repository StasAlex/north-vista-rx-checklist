Предупредить клиента

открыто 7 из 11

  • Касса не проверяет рецепт

    POSоткрыто

    Покупателю с rx-rejected линза пробита и оплачена на кассе (#1013, затем возврат). Locksmith и Checkout Validation на POS не действуют, теги rx-* в карточке покупателя в POS не видны — кассир статус рецепта не знает.

    Варианты: инструкция кассиру проверять статус в админке или POS UI-расширение со статусом рецепта и предупреждением (вероятно, Change Request).

  • Shopify Payments и рецептурные товары

    Платежирешение клиента

    Рецептурные медицинские изделия входят в список ограниченных категорий Shopify Payments. Нужно письменное подтверждение Merchant Support. От ответа зависит процессор онлайн и терминал на кассе — оборудование до ответа не покупать.

  • HIPAA и закон Калифорнии о медданных

    Юристырешение клиента

    Юрист клиента решает, нужен ли режим HIPAA (и CMIA Калифорнии). Схема работает в обоих вариантах: меняется только внешнее хранилище — Airtable или сервис с подписанным BAA.

  • Медданные не хранятся в Shopify

    Архитектураучтено

    Shopify не подписывает BAA, поэтому скан и параметры рецепта лежат только в Airtable. В Shopify — тег статуса и дата окончания. По этой причине Customer Fields из оценки заменён формой Airtable + Make.

  • Доступ меняется не мгновенно

    Makeучтено

    Решение сотрудника в Airtable попадает в Shopify при ближайшем запуске Make (на стенде раз в 60 минут). До этого покупатель видит прежний статус. Частоту запуска выбирать вместе с тарифом Make.

  • Стоимость стека выше, чем в оценке

    Подпискирешение клиента

    В стек добавлен Make. Бесплатного тарифа (1000 операций в месяц) хватает только при редком запуске; для боя — Make Core (около $9 в месяц) или Airtable Team вместо Make. Transactional-письма Klaviyo — только на платном аккаунте.

  • Домен отправки писем

    Klaviyoрешение клиента

    Без собственного домена отправки (DNS на домене клиента) письмо со стенда пришло через общий домен Klaviyo и попало в спам.

  • Депозит за запись: цена визита или зачёт в счёт линз

    Sesamiрешение клиента

    Сейчас $25 при записи превращаются в подарочную карту и списываются на кассе (проверено). Нужно решение клиента: это цена визита или депозит в счёт покупки.

  • Адрес магазина и часовой пояс

    POSучтено

    Самовывоз предлагается только покупателям из страны локации. На стенде локация в Торонто (только для теста); для боя адрес — в Калифорнии, часовой пояс Sesami — America/Los_Angeles.

  • Налог с продаж не настроен

    POSрешение клиента

    На стенде сбор налога не включён ни в одном регионе, поэтому в кассовых чеках налога нет. Регистрация для налога Калифорнии — решение клиента.

  • Время истечения рецепта

    Airtableучтено

    Дата в Airtable считается по UTC: рецепт, истекающий сегодня, станет rx-expired около 16–17 часов по Калифорнии, а не в полночь.

Ошибки и доработки, найденные на стенде

открыто 9 из 11

  • Ложный rx-hold на кассовых заказах

    Flowрешено

    Flow удержания ставил rx-hold на уже выданные POS-заказы (#1012, #1013). Исправлено 23.10: кассовые заказы исключены.

  • Лишние продажи при выдаче и возврате на кассе

    POSоткрыто

    Дважды при выдаче или возврате вместо нужного действия пробита новая продажа (#1012, #1014). Нужна инструкция кассиру.

  • Пропуски синхронизации Make

    Makeоткрыто

    19.10 два запуска не нашли новую заявку, прежний тег сохранился. Повторно не воспроизвелось, причина не установлена (гипотеза — гонка со сбросом отметки Synced).

  • Ошибка Klaviyo останавливает сценарий Make

    Makeоткрыто

    Если модуль Klaviyo в Make падает, не выполняются запись даты в Shopify и отметка Synced. Нужен обработчик ошибок на модулях Klaviyo.

  • Покупатель сменил email

    Makeоткрыто

    Make ищет покупателя по email. После смены email заявка не найдёт покупателя — нужна привязка по Customer ID.

  • Лимит 100 покупателей за запуск Flow

    Flowоткрыто

    Шаг Get customer data берёт до 100 покупателей за запуск. Для боя нужна схема на случай, когда истекающих рецептов больше.

  • Нет напоминаний для короткого рецепта

    Klaviyoоткрыто

    Если рецепт подтверждён меньше чем за 30 дней до окончания, профиль не входит во flow напоминаний — писем «за 30 и 7 дней» не будет.

  • Продления подписки идут мимо чекаута

    Подпискиоткрыто

    Повторные заказы подписки создаются без чекаута, Checkout Validation на них не срабатывает. Защищать должен Flow-удержание; продление после истечения рецепта ещё не проверено.

  • Skip cart в Sesami отправляет всю корзину

    Sesamiоткрыто

    При записи с Skip cart на чекаут ушла вся корзина — в заказ #1015 попала линза-подписка.

  • Ссылка в ошибке чекаута некликабельна

    Locksmithучтено

    Checkout Validation показывает текст без ссылки. Текст ошибки отправляет покупателя в «My prescriptions» из главного меню.

  • Мелкие наблюдения на кассе

    POSоткрыто

    Первая оплата подарочной картой на кассе — Checkout failed, повтор прошёл. В #1012 цена строки $37,99 при цене варианта $39,99 — источник разницы не выяснен.

Ограничения платформ и приложений

открыто 0 из 9

  • Готового приложения FTC-верификации нет

    Ресёрчучтено

    Lensio: Verify Prescriptions удалён из App Store 01.01.2025. Остальные приложения собирают рецепт, но не проверяют его у врача — запрос врачу делается своим процессом (шаблон и журнал в Airtable).

  • Airtable Free не вызывает внешние API

    Airtableучтено

    На Free нет действия для HTTP-запроса; Run a script доступен только на платном Team (и не в пробном). Поэтому тег в Shopify ставит Make.

  • Shopify молча принимает пустой тег

    Makeучтено

    Пустое значение из Make Shopify принял без ошибки. Тег теперь вычисляет формула в Airtable, Make только передаёт его.

  • Flow и заказ без покупателя

    Flowучтено

    Условие «ни один тег покупателя не равен…» для заказа без покупателя ложно. Условие перевёрнуто: проверяется наличие rx-verified, удержание — в ветке «иначе».

  • Klaviyo пропускает письма

    Klaviyoучтено

    Покупатель без подписки на рассылку попадает в Klaviyo как Suppressed, письмо пропускается; Smart Sending тоже пропускает письма. Для писем о рецепте Smart Sending выключен, для боя нужны transactional-письма.

  • Письмо об истечении зависит от тарифа Shopify

    Flowучтено

    Событие rx-expired в Klaviyo шлёт Flow через Send HTTP request — на тарифе Basic этого шага нет.

  • Новые аккаунты покупателей

    Shopifyучтено

    В новых customer accounts только Orders и Profile — ссылку на My prescriptions пришлось добавить в меню.

  • Sesami не засчитывает депозит сам

    Sesamiучтено

    Встроенного зачёта депозита нет. Сделано через Flow: заказ услуги → подарочная карта на сумму → списание на кассе. Без формы товара на странице услуги Sesami не добавляет слот в корзину.

  • Доступ приложения к данным покупателей

    Shopifyучтено

    Protected customer data запрашивается в Partner Dashboard, а не в Dev Dashboard. Токен вида atkn_ из Dev Dashboard не подходит для Admin API — нужен client credentials grant.

Замечания по документам и оценке

открыто 4 из 4

  • Canva «Сбор и хранение рецепта»

    Документыоткрыто

    «Связка $0 через Airtable Automation» неверна: нужен Airtable Team или Free + Make. Лимит вложений Free — 1 GB на базу, для сканов посчитать.

  • Technical Overview и фактический стек

    Документырешение клиента

    Customer Fields заменён формой Airtable + Make (со слов команды — согласовано). Приложение лояльности в документе не названо (в ранней оценке — Smile). Make в документе отсутствует.

  • Формулировки о комплаенсе

    Документыоткрыто

    В оценке журнал проверок назван «required for FTC compliance». По контракту мы отвечаем за техническую реализацию, а не за соответствие законам — формулировки в материалах для клиента держать в этой границе.

  • Секрет приложения на скриншотах

    Безопасностьоткрыто

    client_secret приложения стенда попадал на скриншоты. Перед боем — Rotate в Dev Dashboard; для магазина клиента — новое приложение.
